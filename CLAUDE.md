## Build

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release -DBUILD_TESTING=ON
cmake --build build -j$(nproc)
```

Requires: `cmake`, `g++` (C++20). Lua 5.1.5 is **bundled** (`third_party/lua-5.1.5`) on every platform; no system Lua is used. It is stock 5.1.5, not Redis's patched `deps/lua` (no read-only-table or string-hash patches), and cjson/cmsgpack/bit/struct are PeaDB's own code (`src/lua_*_stub.c`), so table order for long string keys, `cjson.encode` number text and some `struct` formats differ from Redis (delta items 62–63, not yet fixed).

On macOS `-O2` is kept for Release builds so benchmark baselines stay comparable (see `CMakeLists.txt`).

`VERSION` (a plain `MAJOR.MINOR.PATCH` file at the repo root) is the single source of truth for PeaDB's own version, reported by `INFO`'s `peadb_version` field. It reaches the binary as a compile definition, `PEADB_VERSION` (`CMakeLists.txt`: `project(peadb VERSION ${PEADB_VERSION_RAW} ...)` reads `VERSION`, then `target_compile_definitions(peadb_core PUBLIC PEADB_VERSION="${PROJECT_VERSION}")`), not a generated header — deliberately, because `scripts/qa/run_fuzz_sanity.sh` compiles `src/command.cpp` by hand outside CMake with only `-Iinclude`, and a header written into a CMake build directory would be invisible to that build (it passes `-DPEADB_VERSION="$(cat VERSION)"` instead, reading the same `VERSION` file). `include/peadb_version.hpp` `#error`s if `PEADB_VERSION` is undefined, so a build that forgets to define it fails loudly at compile time instead of silently shipping a wrong version. Full rationale: `docs/decisions/p5-cluster-addressing-and-version-provenance.md`.

## Coding Conventions

- **Standard**: C++20. `CMakeLists.txt` sets `-Wall -Wextra -Wno-unused-parameter` on the `peadb_core` library target, `PRIVATE` — there is no `-Werror`, and because the flags are `PRIVATE` (not `INTERFACE`/`PUBLIC`), `src/main.cpp` (the `peadb-server` executable) and every unit-test executable, which only link `peadb_core`, get none of these flags either — they build with whatever the compiler's own defaults are.
- **Style**: Google-based `.clang-format` (2-space indent, 100-column target, attached braces). CI checks all C/C++ files under `src/` and `include/` with clang-format 18.1.8. Use that exact version locally (`python3 -m venv /tmp/peadb-format && /tmp/peadb-format/bin/pip install clang-format==18.1.8`); format changed ranges instead of whole files during normal development. The 2026-10-13 CI repair established the full-tree baseline with the pinned version. `scripts/ci/generate_command_metadata.py` also requires it (`CLANG_FORMAT` may name its executable) so regeneration preserves the format gate.
- **Shell scripts** must run on macOS's bash 3.2: no `mapfile`, `${var,,}` or `${var^^}`.
- **Naming** (conventions, not enforced by any tool — there is no `.clang-tidy` in this repo, and never has been):
  - Namespaces `lower_case` (`peadb::storage`); Classes/Structs `CamelCase` (`DataStore`); Functions `camelBack` for methods, though `src/command.cpp`'s free helper functions are overwhelmingly `lower_case` (`handle_command`, `emit_keyspace_notifications`) — follow the surrounding file rather than this rule when they conflict; Variables `lower_case` (`partition_id`); Constants `UPPER_CASE` or `kCamelCase` for `constexpr`; Member variables `lower_case_` (trailing underscore)
- **Commits**: after each completed, coherent change, commit it without being asked — one concise **single-line** [Conventional Commits](https://www.conventionalcommits.org/) subject (`feat:`, `fix:`, `refactor:`, `docs:`, `test:`, …), imperative mood, no body unless essential. Only commit complete, non-broken states (not mid-task checkpoints). Don't `git push` unless asked. Don't create or switch branch. We want a linear git history.

## Tests

```bash
# Unit tests (fast, no server needed)
cd build && ctest --output-on-failure

# Integration tests (starts/stops peadb-server automatically)
cd build && ../scripts/ci/run_integration_tests.sh

# Single integration test
python3 tests/integration/test_m2_strings_expire.py

# Standalone upstream Redis 7.2.5 native sweep and ratchet (the full local gate
# already includes these). Adopted baselines: compat/redis_suite_ledger.json.
SUITE_MODE=native OUT_DIR=artifacts/redis-native scripts/redis/run_redis_tests.sh
python3 scripts/redis/parse_tcl_results.py artifacts/redis-native --require-complete \
  --out-json artifacts/redis-parity/pass_rate.json --out-md artifacts/redis-parity/pass_rate.md
python3 scripts/ci/check_suite_ratchet.py --results artifacts/redis-parity/pass_rate.json

# Most integration tests use fixed ports; new tests need an unused one
python3 scripts/ci/check_port_collisions.py   # stage `portcheck`: fails on new port collisions
```

Tests find `redis-server` through `tests/integration/_redis_path.py` (the pinned 7.2.5 build first, `PATH` last), so a newer Redis on `PATH` (for example Homebrew 8.x) is only a fallback. For ad-hoc experiments, start servers on an unused `--port` with a scratch `--dir` outside the repo, and stop only the PIDs you started: `pkill -f peadb-server` also kills servers that a running test suite owns.

Tests that do not exercise persistence/restart use `tests/integration/_isolated_server.py` (`IsolatedServer`) for a scratch data directory cleaned after the child is reaped. Replication writes its received RDB even with save points off, so replicas must never share the repository data directory. The replication/promotion QA smoke likewise owns separate temporary data directories; restart tests own explicit `--dir` fixtures instead.

Use `wait_until_ready(port, process=proc, password=...)` from `tests/integration/_readiness.py` after starting a child: it requires authenticated PONG when configured, a matching INFO `process_id`, and child liveness. Callers own startup logs and must stop/wait the child on failure. The integration supervisor's timeout, process-group cleanup and log controls are documented in [scripts/README.md](scripts/README.md).

Provision the exact reference with `bash scripts/ci/ensure_redis_reference.sh` (PR/nightly do this before integration tests); the native DUMP interoperability test fails if Redis 7.2.5 is unavailable. Check persistence and replication changes against the pinned real Redis (`~/.cache/peadb/redis-7.2.5/src/redis-server`, `redis-check-rdb`): load each other's `dump.rdb` and replicate in both directions. PeaDB-only round trips cannot catch format bugs; they hid the wrong RDB CRC64.

Sanitizer build and integration settings live in the [nightly workflow](.github/workflows/nightly.yml). Its `PEADB_TEST_SANITIZED` mode retains functional allocator/eviction checks, leaves the RSS ceiling to Release CI, and gives bulk AOF replay a longer socket timeout.

**The parity ratchet**: adopted upstream suites must stay at 0 `[err]`; growing a skipfile (`scripts/redis/skipfiles/`) or lowering a ledger count requires updating `compat/delta.md` in the same change. See the "Verification" section of `compat/delta.md`.

### Adopting an upstream TCL suite

The parity work adopts one upstream suite (or a small batch) per commit:

1. **Baseline** the suite natively: `cd ~/.cache/peadb/redis-7.2.5 && SUITE_MODE=native REDIS_SERVER_BIN=<repo>/peadb-server ./runtest --single unit/<suite> --clients 1 --tags "-tls -cluster -modules -needs:pfdebug -leaks" --dont-clean [--skipfile <repo>/scripts/redis/skipfiles/<suite>.skip]`. The TCL control server uses a fixed port (21079) — only one `runtest` at a time; kill leftovers with `pkill -f test_helper.tcl`.
2. A suite counts as adopted only when it **runs to completion** (`exit 0` / "All tests passed") — not merely `err=0`; a mid-suite hang records a truncated-but-green ok count.
3. The pinned **Redis C source** (`~/.cache/peadb/redis-7.2.5/src/`) is the spec for exact error strings and semantics; `assert_match` is case-sensitive.
4. **Skipfile only what's genuinely out of reach**; every skip line carries a comment naming its `compat/delta.md` item, added in the same commit (the ratchet enforces this).
5. **Register**: add the suite to `SUITES` in `scripts/redis/run_redis_tests.sh` and a baseline entry to `compat/redis_suite_ledger.json` (canonical counts from a `-leaks`-tagged run; `ignored` = `[ignore]` + `[skip]`).
6. Regenerate + validate: `parse_tcl_results.py`, `check_suite_ratchet.py`, `generate_compat_scoreboard.py`, `check_compat_delta.py`; update `CHANGELOG.md` (`[Unreleased]` wave entry) and `compat/delta.md`; then run both mandatory pre-commit checks below.

**After every set of changes that is ready to commit, you MUST run both of these and confirm they pass before considering the work done:**

```bash
# 1. Full test suite (unit + integration)
bash scripts/run_all_tests.sh

# 2. Performance regression check (must not get worse vs Redis baseline)
bash scripts/dev/redis_vs_peadb_benchmark.sh
```

Do not skip either check. Do not commit if either fails.

`run_all_tests.sh` runs 11 stages and takes about 40 minutes: start it in the background and wait for it, because a tool timeout (about 10 minutes) stops it early and looks like a failure. `redis_vs_peadb_benchmark.sh` needs Docker host networking, so it only works on Linux; on macOS, report it as not run (a PeaDB-only `redis-benchmark` run is a smoke check, not the comparison).

Release image publication additionally requires the [migration acceptance gate](docs/compatibility.md#migration-acceptance-gate), using more than two million keys in both directions. The normal integration test is explicitly a small smoke, not release-scale evidence.

## Architecture

PeaDB is a Redis 7.2.5-compatible server written in C++20. For a fuller contributor-facing overview (execution model, data structures, persistence, replication, roadmap), see [`docs/architecture.md`](docs/architecture.md).

- **`src/command.cpp`** — All Redis command handlers in one file (authoritative command list/count: `compat/commands.generated.md`). The command table is built once in `command_table()` (a static local). `handle_command()` is the main dispatcher.
- **`src/config_rewrite.cpp`** — Redis-style typed/special configuration writers and atomic publication; `main.cpp` retains the absolute startup config path before the loader applies `dir`. `CONFIG REWRITE` reads authoritative live values and the current role; see `compat/delta.md` item 25 for boundaries and Redis-first regressions.
- **`src/server.cpp`** — Single-threaded epoll/kqueue event loop. Manages client sessions (`SessionState`), write buffers (`WriteBuf`), blocked clients, clients held by `CLIENT PAUSE` (`SessionState::postponed`: the held command stays in the input buffer and runs again when the pause ends), clients blocked on a `SHUTDOWN` that waits for replicas (`SessionState::blocked_on_shutdown`; `g_reply_blocked_on_shutdown_cb` answers them when the shutdown fails or is aborted), and deferred WAIT replies. Calls into command.cpp for every client command.
- **`src/datastore.cpp`** — In-memory key-value store (`DataStore`), 16 independent databases, all standard Redis data types (string, hash, list, set, zset, stream). The keyspace of each database and the hash, set and sorted-set member tables are `peadb::Dict`s (`include/dict.hpp`): chained hash tables with a power-of-two bucket count like Redis's `dict.c`, which double at one element per bucket and shrink under 10% full (collections after a delete, the keyspace from `databases_cron()` when no fork child runs), but rehash all at once (delta item 13); string keys hash with SipHash-1-2 under a random per-process key (`DictStringHash`, like Redis's `dictGenHashFunction()`), and `erase(iterator)` returns nothing so it stays O(1) in a sparse table. SCAN/HSCAN/SSCAN/ZSCAN follow Redis's `scanGenericCommand()`: `Dict::scan()` is `dictScan()`'s reverse-binary cursor, so every element present for the whole scan is returned however the table resizes, and a call stops after COUNT elements looked at or COUNT × 10 buckets (`scan_dict()`); MATCH uses `fnmatch()`, not Redis's matcher (delta item 76, not yet fixed). Random-start active expiry.
- **`src/rdb.cpp`** — RDB binary format reader/writer. Non-stream types use real Redis type bytes, and the trailing checksum is Redis's CRC-64 (`crc64()`, declared in `include/rdb.hpp`: Jones polynomial, reflected, 8 bytes per step like Redis's `crcspeed.c`; known answers in `tests/unit/rdb_crc64_test.cpp`), so PeaDB and Redis load each other's RDB files, full syncs, DUMP payloads and FUNCTION DUMP payloads (`rdb_dump_functions()`/`rdb_parse_function_payload()`; checked by `tests/integration/test_rdb_redis_interop.py`). Lists are written as quicklist nodes split like Redis's `quicklistPushTail()` for `list-max-listpack-size` (`write_quicklist()`; for a list built by RPUSH the same nodes as Redis, checked by `tests/integration/test_rdb_list_nodes.py`), and every listpack is checked on load like Redis's `lpValidateIntegrity()` (the entry count is not checked, as in Redis with `sanitize-dump-payload no`); the shared reader also validates and converts pre-7.0 zipmap/ziplist encodings, and full sync validates database ranges/values before replacement (delta item 53; regression in `tests/integration/test_rdb_legacy_interop.py`). Streams use native Redis RDB v11/type 21 through a shared writer for SAVE/BGSAVE/PSYNC/DUMP and a shared validated decoder for RDB load/RESTORE; stream types 15/19/21 and old private type 200 load. Snapshots preserve history, groups, empty consumers, seen/active timestamps and PEL metadata; `tests/integration/test_dump_native_interop.py` checks real Redis in both directions. See `compat/delta.md` items 2, 5 and 51 for remaining boundaries.
- **`src/lua_engine.cpp`** — Lua 5.1 scripting (EVAL/EVALSHA/FCALL), wired back to `handle_command` for Redis call dispatch.
- **`include/command.hpp`** — `SessionState`, `BlockedState`, `WaitState` structs; all extern globals and callbacks shared between command.cpp and server.cpp.
- **`include/datastore.hpp`** — `DataStore` class and `Entry`. `Entry` is a **tagged union** (`std::variant` over the inline string + five heap-held collection payloads), so only the active type allocates: ~56 bytes + the active payload, down from the old fat struct that carried all six payloads at once (~328 B libc++ / ~456 B libstdc++). `expire_at_ms`, `lru`, and `string_force_raw` stay inline; typed accessors (`str()`/`hash()`/`list()`/`set()`/`zset()`+`zord()`/`stream_*()`) lazily materialize the active alternative, and a hand-written deep-copy ctor clones it (the `unique_ptr` members make the default copy ill-formed). `type()` is `payload.index()`. All payload access is confined to `src/datastore.cpp`.

## Key Conventions

- Anonymous namespace in `command.cpp` contains all helpers and globals. Public functions are defined after `} // namespace` (before `} // namespace peadb`).
- Globals in `command.cpp` anonymous namespace are accessible from public functions in the same file via the same-TU rule.
- `SessionState::fd` must be set before BLPOP/BRPOP block — used by `register_key_waiter`.
- Persistence: AOF uses a persistent fd (`g_aof_fd`) opened at startup by `configure_persistence()`, which stops startup when it cannot open it. Like Redis's `loadDataFromDisk()`, `main.cpp` loads the AOF when `appendonly yes` and the RDB otherwise, never both (even an empty AOF means the RDB is not read). `fsync` policy controlled by `g_appendfsync` ("always"|"everysec"|"no"). AOF writes follow Redis's `flushAppendOnlyFile()` (`flush_append_only_file()`): a failed or short write keeps the unwritten bytes in `g_aof_buf` (a short write is cut off with `ftruncate()`) and sets `g_aof_write_error`, a failed everysec fsync sets `g_aof_fsync_error`; `aof_cron()` (every event-loop pass) writes the kept bytes again and runs the everysec fsync of new bytes (and retries a failed fsync every second), and a good write or fsync clears its error; under `always` a failed write or fsync `_exit(1)`s before the reply goes out; a good AOF rewrite drops `g_aof_buf` (the new file holds it), and a shutdown refuses to exit while `g_aof_buf` cannot be written (unless FORCE). Writes reach the AOF and the replication backlog through execution units, Redis's `alsoPropagate()`/`propagatePendingCommands()`: `propagate_write()` (the dispatch chokepoint and handlers that propagate their own effects) canonicalizes a write and `also_propagate()` queues it in `g_also_propagate` while `g_execution_nesting > 0`; `ExecutionUnit` (around each command's handler in `handle_command()`, and in `try_unblock_client()`) runs `propagate_pending_commands()` when the outermost unit ends, which writes each stream once (`append_aof_payload()`, `backlog_append()`), with a SELECT inside, and wraps the unit in `MULTI`/`EXEC` when it has more than one write (EXEC, scripts, functions, XREADGROUP; not SCAN/RANDOMKEY, Redis's `CMD_TOUCHES_ARBITRARY_KEYS`); evictions, active expiry and other event-loop writes go out at once (`propagate_now()`), and so does the outermost command's own write when it is the unit's only one (`last_of_unit`, the hot path); `PUBLISH`/`SPUBLISH` go to the replicas only. Stream handlers return per-mutation `DataStore::StreamClaimEffect` snapshots and use `propagate_stream_effect()` (`also_propagate`, both targets even under `redis.set_repl(NONE)`, as Redis does); `CommandSpec::propagates_effects`, cached before renames, prevents a second implicit propagation. Claims carry absolute TIME, explicit RETRYCOUNT and LASTID; NOACK uses per-occurrence `StreamGroupEffect` snapshots, and NOACK/group-cursor-only changes use XGROUP effects. A write handler that changed nothing (a `SET` stopped by `NX`/`XX`, `SETNX`/`MSETNX` answered 0, a `GETEX` that set or removed no TTL, a `GETDEL`/`SETRANGE`/`PERSIST`/`SORT` that changed nothing, a `RESTORE` whose TTL had passed and that deleted no key) sets `g_write_changed_nothing`, so `handle_command()` skips its propagation, its change count and its keyspace events, as Redis's `call()` does for a command that did not move `server.dirty` (delta item 41); every other successful write still counts (item 18). BGSAVE/BGREWRITEAOF fork through `fork_child()` (Redis's `redisFork()`: in the child, `log_in_forked_child()` makes `log()` lock-free and `g_close_sockets_in_child_cb`, wired by server.cpp, closes the listeners and client sockets) and are reaped by `reap_background_children()`; like Redis only one child runs at a time (`has_active_child_process()`): `BGSAVE SCHEDULE` and a BGSAVE inside `MULTI`/`EXEC` set `g_rdb_bgsave_scheduled`, and `BGREWRITEAOF` or `CONFIG SET appendonly yes` beside a BGSAVE or inside `MULTI`/`EXEC` (or a script, for BGREWRITEAOF) set `g_aof_rewrite_scheduled`, which `reap_background_children()` starts once no child runs (a rewrite forked inside a unit would hold its first writes in the child's dataset and the rewrite buffer). Save points (`g_save_params`, parsed by `configure_save`) fire `do_bgsave_fork()` from `background_save_cron()` in the event loop (after a failed BGSAVE only 5 s after `g_lastbgsave_try`). `do_bgsave_fork()` and the reaper follow Redis's `rdbSaveBackground()`/`backgroundSaveDoneHandlerDisk()`: a failed fork or child sets `g_last_bgsave_status` to `err` with Redis's log lines, and the change count (`mutation_epoch() - g_dirty_at_last_save`) and `g_last_save_time` (INFO, `LASTSAVE`) move only after a good save (`note_rdb_saved()` for the foreground saves). `FLUSHALL` stops a BGSAVE child (`kill_rdb_child()`) and, with save points, saves at once (Redis's `flushAllDataAndResetRDB()`). Every RDB save writes `temp-<pid>.rdb` and renames it (`rdb_save()`, like Redis's `rdbSave()`). `SHUTDOWN` and SIGTERM/SIGINT share `prepare_for_shutdown()` (Redis's `prepareForShutdown()`: without `NOW`, with `shutdown-timeout` (`g_shutdown_timeout`) not 0 and a replica whose `repl_ack_offset` is not `g_master_repl_offset`, it sends `REPLCONF GETACK *`, pauses writes with `pause_actions(kPauseDuringShutdown, …)` (pauses are kept per purpose, `g_pause_per_purpose`, like Redis's `pauseActions()`), sets `g_shutdown_mstime` (`shutdown_initiated()`, INFO `shutdown_in_milliseconds`) and returns false; the SHUTDOWN client is then blocked, `SessionState::blocked_on_shutdown`) and `finish_shutdown()` (Redis's `finishShutdown()`: log lagging replicas, kill a BGSAVE/AOF-rewrite child, fsync the AOF, final save; a failure runs `cancel_shutdown()`, which ends the pause and answers the blocked clients through `g_reply_blocked_on_shutdown_cb`); the signal handler (`shutdown_signal_handler()`, installed in `main.cpp`) only sets `g_shutdown_asap`, and `shutdown_cron()` at the top of each event-loop pass starts the shutdown with the `shutdown-on-sigterm`/`-sigint` flags and finishes a waiting one once the replicas are in sync or the time is up (held by DEBUG PAUSE-CRON; SHUTDOWN ABORT cancels both). `CLIENT UNBLOCK` does not release a blocked SHUTDOWN client (Redis 7.2.5 crashes there). Write commands (Redis's write flag, `spec_command_flags()`, which reads a script's declared flags), `PING` and an `EXEC` whose transaction writes are rejected with the `-MISCONF` reply of `misconf_reply()` (failed bgsave + save points, or an AOF write or fsync error, each with Redis's text; also at MULTI queue time, never for `g_replaying_aof`, and not for a script that has already written, `g_script_write_dirty`, Redis's `SCRIPT_WRITE_DIRTY`), checked after `-OOM` (`maxmemory_refuses()`, see Eviction). These checks of a client's command follow Redis's `processCommand()` order (`-OOM`, `-MISCONF`, `-NOREPLICAS`, `-READONLY`, the RESP2 pub/sub context, `-MASTERDOWN` for a command Redis does not flag `STALE` on a stale replica) and Redis's command flags (`command_flags()`; `CommandSpec::redis_name`/`redis_flags` keep them under `rename-command`), for a command run at once and for one queued in `MULTI` (which flags the transaction); `EXEC` is checked by the flags its commands had when queued (`SessionState::multi_flags`/`multi_inv_flags`, Redis's `mstate.cmd_flags`/`cmd_inv_flags`) and refused with `-EXECABORT Transaction discarded because of: <error>`, and the commands `EXEC` runs are not checked again. A script's commands are checked like Redis's `scriptCall()` (the stale check in `dispatch_from_lua()`, then the first write's `-READONLY`/`-MISCONF`/`-NOREPLICAS` and `-OOM` in `handle_command()`), and scripts and functions before they run by `script_prepare_refusal()` (Redis's `scriptPrepareForRun()`). The OOM step and `noreplicas_should_reject()` never refuse AOF replay or the master stream (`g_replaying_aof`) and never refuse on a replica (Redis's `mustObeyClient()`, `replica-ignore-maxmemory yes`, `checkGoodReplicasStatus()`).
- Expiry follows Redis's `expireIfNeeded()`: every erase of an expired key goes through `DataStore::remove_expired()`. On a master it deletes the key and calls the lazy-expire hook, `propagate_lazy_expire()` (installed by `configure_lazy_expire()` from `main.cpp`), which queues a `DEL` for the AOF and the replicas with `also_propagate()` (whatever `redis.set_repl()` says; inside a command it joins the command's execution unit) and sends the `expired` event; the active cycle uses the same path. On a replica (`set_replica_expiry(true)`, set by `REPLICAOF`) a lookup only hides the key until the outermost `ExecutionUnit` ends (`restore_hidden_expired()`); the master's `DEL` deletes it. Inside `DataStore::LazyExpireDisabled` no key counts as expired: AOF load, the master stream, RDB save and load, and the dispatch's bookkeeping lookups after a handler (`canonicalize_propagated_command()`, the event checks), which must never delete a key the command left with a past expire time. Reads that must have no effect use `live_type()`/`watch_digest()` (blocked-client wakeups, WATCH/EXEC); `KEYS` and `for_each_key()` delete nothing. A key is expired when `now > expire time`; EXPIRE-family and GETEX `EXAT`/`PXAT` with a past time delete the key at once (`already_expired()`, Redis's `checkAlreadyExpired()`). There is no per-command time snapshot outside scripts (delta item 75).
- Eviction and the OOM check follow Redis's `processCommand()` and `evict.c`: `maxmemory_refuses()` (in `handle_command()`, for a client's own command only: not the commands EXEC or a script runs, never `g_replaying_aof`) runs `perform_evictions()` (`performEvictions()`: bytes to free from `used_memory` less `free_memory_not_counted()` — the replicas' output buffers via `g_replica_output_buffers_cb` (server.cpp walks only `replica_fds`) and the AOF buffers, sized by `zmalloc_string_bytes()` —, victims from `DataStore::evict_one(policy, g_maxmemory_samples)`, at most `eviction_time_limit_us()` from `maxmemory-eviction-tenacity`, then `start_eviction_time_proc()`; not on a replica, during CLIENT PAUSE or a busy script), then refuses with `-OOM` a `denyoom` command (`command_flags()`, Redis's `getCommandFlags()`: generated `kRedisCmdDenyoom`, and for EVAL/EVALSHA/FCALL with declared flags `scriptFlagsToCmdFlags()`), an EXEC whose queue holds one (`-EXECABORT … because of: OOM …`), or anything but EXEC/DISCARD/QUIT/RESET inside MULTI, and stores `g_pre_command_oom_state`; inside a script `script_refuses_for_oom()` (`scriptVerifyOOM()`: only if that state is set and `g_script_write_dirty` is not, unless `g_script_allow_oom`). `run_eviction_cycle()` (every event-loop pass) keeps `g_used_memory_peak` and, while `g_eviction_proc_running` (a pass that hit its time limit, or `CONFIG SET maxmemory`, which also logs Redis's warning), evicts again; the event loop does not sleep then (`eviction_proc_running()`). Each victim is propagated as `DEL` to backlog + AOF after a `SELECT` of its database, queued in the pass's non-wrapping `ExecutionUnit(nullptr, false)` (one AOF write per pass, like the active expiry cycle), and emits `notify_keyspace_event(NOTIFY_EVICTED, "evicted", …)`. Policy enum is `MaxmemoryPolicy` (datastore.hpp); `apply_maxmemory_policy()` also sets `store().set_eviction_lfu()`. Per-key LRU/LFU lives in `Entry::lru` (Redis's 24-bit seconds LRU clock, `lru_clock()`/`lru_idle_seconds()` in `src/datastore.cpp`, or the LFU counter; `Entry::lru_fresh`: a new key's first touch sets `LFU_INIT_VAL`), touched in `DataStore::get()` and at the dispatch chokepoint (`touch_key_for_eviction`, first key only); there is no eviction pool (delta item 12). The keyspace `Dict`s refuse to double over `maxmemory` (`KeyspaceExpandAllowed`, `dict_expand_allowed()`, Redis's `dictExpandAllowed()`). Config: `configure_maxmemory`/`configure_maxmemory_policy`/`configure_maxmemory_samples`, CONFIG GET/SET `maxmemory`/`maxmemory-policy`/`maxmemory-samples`/`maxmemory-eviction-tenacity`, `--maxmemory*` CLI.
- Memory accounting: `zmalloc_used_memory()` (`include/zmalloc.hpp`, `src/zmalloc.cpp`): the global `operator new`/`delete` are replaced and keep one relaxed atomic count of the allocator's size of every live block (`malloc_usable_size()`/`malloc_size()`), like Redis's `zmalloc`; O(1), and it includes client buffers, the backlog and container overhead (Lua's `realloc()` memory is not counted, as in Redis). INFO's `used_memory` and the maxmemory checks use `used_memory()` in `src/command.cpp`: that count less the part of the replication backlog ring no write has reached (`ReplBacklog::unused_bytes()`; the ring is not zero-filled, so that part is not resident), and less the whole ring until a replica has attached (`g_backlog_has_replica`), since Redis has no backlog before its first replica. Code that empties a big buffer should give it back (`clear_buffer()` for the AOF buffers, `release_drained()` in server.cpp for client buffers over 64 KB), because a kept `capacity()` counts against `maxmemory`. `maxmemory` is parsed with units via `parse_memory()` / `configure_maxmemory()`. `MEMORY USAGE` is still a rough per-type estimate, and INFO's keyspace section still walks every key (delta item 55).
- Robustness: server.cpp wraps dispatch in `safe_handle_command()` (one bad command can't kill the loop); `main.cpp` installs fatal-signal crash handlers (backtrace) + `std::set_terminate`; a corrupt AOF is fatal at startup while a truncated tail (or an unfinished `MULTI`) is cut off the file at the last whole command, like Redis's `aof-load-truncated` (`load_aof_file()`/`read_aof_step()`). Every RDB load (startup, DEBUG RELOAD, a replica's full sync) checks the trailing CRC64 like Redis's `rdbLoadRio()`, but before `rdb_load()` flushes the dataset (DEBUG RELOAD flushes first itself, as in Redis): skipped when `rdbchecksum no` (startup-only; `rdb_set_checksum()`, then saves write a zero checksum) or DEBUG SET-SKIP-CHECKSUM-VALIDATION is on, and a stored 0 means "saved without a checksum"; a file newer than RDB version 11, or one without the EOF opcode and checksum bytes (cut short), is refused. A corrupt native (`REDIS`-magic) dump is fatal in `main.cpp` rather than falling back to legacy.
- Observability: one timing wrapper at the dispatch chokepoint (`command.cpp`, around `spec.handler(...)`) feeds `CmdStats::usec_total` (INFO commandstats), `slowlog_add()`, and `latency_add()`. Keyspace notifications are emitted centrally by `emit_keyspace_notifications()` after a successful write (+ `"expired"` from `propagate_lazy_expire()`, see Expiry), gated by `g_notify_flags` (parsed from `notify-keyspace-events`); that table sends at most one event for the first key, so many commands miss events (delta item 72, not yet fixed). Handlers that need Redis's exact sequence call `notify_keyspace_event()` themselves and are left out of the table: the list and sorted-set edits (LSET, LREM, LINSERT, LTRIM, ZREM, ZREMRANGEBY*, which also send `del` when they empty the key) and the stream group commands. `MONITOR` uses `g_monitor_fds` (fed by `feed_monitors()`, cleared in `on_client_disconnect()`); `CLIENT KILL` goes through `g_client_kill_cb` (server.cpp owns fd close). INFO RSS via `process_rss_bytes()`, CPU via `getrusage`.
- Full-sync master: `ReplicaSyncState` separates waiting, saving, bulk transfer and online replicas. `start_replication_snapshot()` uses the shared BGSAVE child, and `g_replication_snapshot_done_cb` opens its completed snapshot before later saves run. `SnapshotTransfer` keeps RDB bytes separate from the limited command buffer; failure callbacks defer closes until dispatch ends. Implementation and acceptance: [docs/architecture.md](docs/architecture.md), delta 46.
- Replication authentication: config/CLI and CONFIG GET/SET apply `masteruser`/`masterauth`; the supervisor reads one pair under `g_masterauth_mu` after PING, and CONFIG SET holds it across applies/rollback. Empty password skips AUTH; empty username selects AUTH password; otherwise AUTH username/password. Runtime changes apply at reconnect. The regression `test_replication_auth_parity.py` requires a Redis reference and prints its version; use the pinned 7.2.5 build for acceptance (delta 50).
- Replica persistence/startup: `configure_replication()` must run before disk loading, RDB startup calls `restore_rdb_replication()` only after successful loading, and `start_configured_replication()` runs after event-loop initialization. Restart history semantics and regressions are in delta item 47. Master commands persist their effects, while AOF replay stays suppressed; received RDB replacement stops old persistence children. See [docs/architecture.md](docs/architecture.md) and delta item 45.
- Replication: REPLICAOF spawns a generation-tagged (`g_repl_generation`) supervisor thread that auto-reconnects with backoff via `replica_do_fullsync(host, port, gen)`; it stops when the generation changes (a newer REPLICAOF / NO ONE). The streaming loop checks the generation each ~1 s recv tick. That link thread only reads: it queues each command of the master's stream with its bytes (`MasterStreamCommand` in `g_replica_cmd_queue`) and wakes the event loop through a pipe (`set_replica_wakeup_fd()`/`take_replica_wakeup()`); the full-sync RDB (staged in `temp-<unixtime>.<pid>.<generation>.rdb` in the working directory), the master's replid and offset are handed to the event loop too, tagged with the link's `REPLICAOF` generation (`g_replica_load_gen`), and the event loop drops a hand-off from a replaced link. The event loop applies the stream with one `SessionState` (`g_master_stream_session`, `drain_replica_cmd_queue()`), new for each full sync, so a `MULTI` cut off by a broken link is dropped, and after each applied command adds its bytes to the replica's own stream with `backlog_append()` (a transaction only once its EXEC has run, `g_master_stream_multi`), like Redis's `replicationFeedStreamFromMasterStream()`: so on a replica `g_master_repl_offset` is the offset of its master's stream it has applied, its own replicas get that stream byte for byte, and a promotion continues from it (delta items 44 and 47). The event loop sends the replica's `REPLCONF ACK` with that offset (`send_replica_ack()`, every second from `replication_cron()` and when it applies a `REPLCONF GETACK`, with the offset before the GETACK, as Redis does); the link socket is published in `g_replica_link_fd` under `g_replica_link_mu`. A full-sync RDB carries `repl-stream-db` (`RdbReplicationInfo`), which a replica reads to start its stream session in that database. On the master, `backlog_append()` hands every replica what it has not taken from the ring, and the new bytes, in its output buffer (`g_feed_replicas_cb`, server.cpp) before the ring would overwrite them (`g_replicas_taken_to`), so no replica loses bytes when more than `repl-backlog-size` is written in one pass (delta item 40); `attach_replica()` makes a client a replica (a master's first replica starts the backlog with a new replid, `start_backlog()`, like Redis's `syncCommand()`), and `+CONTINUE` names the replid for a `capa psync2` replica. `REPLICAOF <host> <port>` answers clients blocked on keys or in WAIT with `-UNBLOCKED` (`g_unblock_blocked_clients_cb`, Redis's `disconnectAllBlockedClients()`); clients that a command answers on another client's behalf (CLIENT UNBLOCK, a cancelled shutdown, that) run their pipelined commands afterwards from `run_released()` in server.cpp, never inside the command. Active expiry runs only on the master (`run_active_expire_cycle()` no-ops on a replica) and propagates `DEL` to the backlog. `noreplicas_should_reject()` gates writes on the real connected-replica count. Backlog size is `g_repl_backlog.size_` (set by `configure_repl_backlog_size`). The replid is randomized per process (`init_replication_id()`, called in `main.cpp`); `REPLICAOF NO ONE` rotates it into `g_master_replid2`/`g_second_replid_offset`, forces a SELECT (`g_last_repl_db = -1`) and disconnects the replica's own replicas (`disconnect_replicas()`), and PSYNC accepts a partial resync against that history. Replica reconnects use event-loop-owned cached history through `MasterLinkRequest` (applied offset + 1; pending RESP/MULTI dropped; blocked masters require full sync). CONTINUE adopts a changed replid and disconnects downstream replicas; the validated RDB replacement boundary invalidates old cache/backlog. Nonblocking connect/handshake/transfer/stream I/O checks generations and live `repl-timeout`, replica sockets use TCP keepalive, and masters emit periodic PINGs and disconnect silent ACKs (delta 47, fixed). Master-side full sync forks and streams a disk-backed snapshot (delta 46, fixed). PSYNC increments `g_sync_full`/`g_sync_partial_ok`/`g_sync_partial_err` (INFO Stats). `WAIT` waits for the client's own last write (`SessionState::woff`, set by `WriteOffsetTracker` around each command's `ExecutionUnit`, Redis's `c->woff`); its `REPLCONF GETACK *` goes into the stream once per event-loop pass after the pass's commands (`send_pending_getack()`, Redis's `beforeSleep()`), so replicas ACK within ~1 RTT.
- Lazyfree: `DataStore::unlink()` (UNLINK) detaches big values (>64 elements) via `db.extract` and `flushall_async`/`flushdb_async` (FLUSH `ASYNC`) swap the whole db map out, handing the detached `DB` to a background worker thread (`lazyfree_thread_` + mutex/condvar queue) that destructs it off the event loop. Safe under single-writer because ownership is moved out of the live keyspace before handoff; `~DataStore()` joins the thread. Per-class output-buffer limits live in `g_cobl[3]` (`configure_client_output_buffer_limit`); server.cpp closes overflowing clients (`obuf_overflow_fds`). Idle clients are reaped by `client_timeout_seconds()` (server housekeeping), exempting replicas/blocked/MULTI/`client_has_subscriptions()`.
- Config loading (`src/config.cpp`) follows Redis 7.2.5's `loadServerConfig()`: the file, then stdin (`-`), then `--name value` options turned into config lines (`config_options_from_argv`, a port of Redis's `main()` loop), all parsed as one text, so the last value wins. Names, aliases, types, ranges, enum values, flags (immutable, protected, hidden, sensitive) and defaults come from `include/redis_config_table.generated.hpp` (`scripts/ci/generate_redis_config_table.py`, generated from the pinned `config.c` and `server.h`; re-run it after a Redis pin bump). Anything Redis's loader refuses stops startup with Redis's error text; a `dir` line `chdir()`s at once, as in Redis, so the data file names (`g_snapshot_path`, `g_aof_path`) are relative to the working directory; Redis settings PeaDB does not apply are decided on their final value in `finish_load()` — refused when PeaDB cannot honour them safely (`fixed_settings()` entries with a `refuse` reason), otherwise accepted with one warning each (delta item 24). `CONFIG GET`/`CONFIG SET` (`config_get_reply()`/`config_set_reply()` in `src/command.cpp`) follow Redis's `configGetCommand()`/`configSetCommand()` and share the loader's value checks (`check_redis_config_value()`); a setting PeaDB applies has a getter and setter in `live_configs()`, a fixed one (`peadb_fixed_setting()`) refuses any other value, and any other one is kept in `g_config_values` with a warning (delta items 23–25). `rename-command` is checked while loading, against Redis's command table (`handle_rename()`); `command_table()` applies the checked renames. Test launches must use Redis's loglevel names (`warning`, not `error`). `--config <path>` is PeaDB's only non-Redis option.
- Cluster: four config options — `cluster-enabled` (startup-only, like Redis's own `IMMUTABLE_CONFIG` treatment; refused by `CONFIG SET`), `cluster-announce-ip`/`-port`/`-bus-port` — are parsed into `ServerConfig` (`include/config.hpp`) and read back through `cluster_announced_host()`/`cluster_announced_port()`/`cluster_announced_bus_port()` (`src/command.cpp`); an unset announce-ip falls back to `bind`, and with `cluster-enabled yes` the server refuses to start if that fallback would resolve to a wildcard (`0.0.0.0`, `::`, `*`, or empty). Node ids are `sha1_hex("peadb-cluster-node:" + host + ":" + port)` — deterministic from the announced address rather than random-and-persisted, since there is no `nodes.conf`. Full design rationale (including what is and is not gossiped): `docs/decisions/p5-cluster-addressing-and-version-provenance.md`. Cluster mode is not production-safe yet: routing hashes only the first key (no CROSSSLOT), there is no CLUSTERDOWN, and nodes neither share nor persist slot ownership (delta items 64–67; item 6 is marked `experimental`).
- Security: `handle_command()` gates on `g_requirepass` — when set, unauthenticated sessions (`SessionState::authenticated`) get `-NOAUTH` unless the command is flagged `no_auth` (AUTH/HELLO/QUIT/RESET). Internally replayed/replicated commands bypass the gate via `g_replaying_aof`. `configure_security()` (called from `main.cpp` before the first `command_table()` build) wires `requirepass`/`masterauth`/`protected-mode`/`enable-module-command`/`rename-command`. protected-mode is enforced in the server accept loop (`protected_mode_enabled()`/`requirepass_is_set()`). `MODULE LOAD` requires `enable-module-command`. Only `requirepass` sets a password; config-file `user` and `aclfile` lines stop startup (delta item 24). Protocol limits (`proto-max-bulk-len`, multibulk cap) live in `protocol.cpp`; the server closes the connection when `handle_command` sets `should_close` for a protocol error.

## Compatibility

`compat/delta.md` is the canonical status registry for known gaps vs Redis 7.2.5. `compat/commands.generated.md` is auto-generated by `scripts/ci/generate_compat_scoreboard.py`.

Feature status labels: `full` | `partial` | `surface` | `stub` | `experimental`.

Master-stream commands and AOF replay use `must_obey_client()` to bypass client gates and cluster routing (delta 43, fixed). `handle_command()` logs replay errors, including individual errors inside EXEC, and counts `unexpected_error_replies`; master writes stop a replica with persistence errors unless `replica-ignore-disk-write-errors yes`, which is applied at startup and runtime. The outgoing replica flag `SessionState::replica_stream` does not identify the incoming master; `g_applying_master_stream` does.
